# Reader architecture and polish plan

Status: Accepted direction, 2026-11-01; implementation and acceptance ongoing. [ADRs 0007–0010](adr/README.md) govern rendering/native ownership, consistent presentation, selection/annotations and navigation/reflow. Apple Books is the experience reference; its private implementation is unknown. This plan does not certify the 0.3 release.

Current local runtime: `d04d8c3c26f9271167a00f33330db9d2320c4e35` passed Mac and signed iPhone development builds, signatures and affected renderer/native fixtures. It is installed on Mac. Native real-book checks exercised the live inspector, toolbar order, sepia chrome and independent page-control toggling. The bounded fixture preserves anchors and ordered turns through resize/reversal; sustained visual performance, physical devices, accessibility and Apple Books comparison remain separate acceptance. See [VALIDATION.md](../VALIDATION.md) and [the scoped checkpoint](UI_REFINEMENT_2026-11-03.md). Earlier runtime records are historical.

1. **Stabilize reading tools.** Keep the owner-verified native EPUB selection-menu actions and address real-book, selection-lifetime and edition-verification problems. Complete existing-highlight editing, color/underline changes, note-only removal and full removal. Test save/reopen, search, jump and export, including invalid anchors and write failure recovery. Confirm iPhone, iPad and Mac behavior and accessibility independently. Measure the selection observer before choosing its long-term design. See ADR 0009.
2. **Prioritize visual and interaction polish.** Improve visible behavior and its underlying architecture together. Address turns, fade/dark curl, cover opening, details, spacing, sidebar and reflow using owner feedback. Honor every committed swipe exactly once and in order, including reversals; shorten or interrupt decoration to catch up quickly. Never replace or cap pending navigation merely because rendering is behind. Following the owner’s revised direction on 2026-11-03, hold one frozen, softened visible page during direct resizing and inspector movement while reflow completes behind it. Reveal the final layout only after matching native paint and observed geometry settlement; the earlier visibly live reflow direction is superseded. Keep reader chrome visibility independent of inspector state. Bounded hold/dissolve remains an evaluated typography technique. Rapid-card and curl ownership work is integrated locally; assess cold-capture behavior and actual ordered gestures against ADR 0010 before accepting the interaction.
3. **Tighten presentation and renderer ownership incrementally.** Define validated commands/events, session/layout ownership, stale-result rejection and teardown. Keep publication scripts disabled, resources local and provider logic outside the renderer. Apply uniform reflowable styling while preserving semantic structure; validate the implemented per-book Original Formatting and fixed-layout fallback without rewriting the document or losing anchors. Retain EPUB.js initially. Refactor only as needed for the observed integration/performance problems. See ADRs 0007–0008.
4. **Complete offline and synchronization outcomes.** Continue durable downloads, user-selected folders, import, recovery and storage acceptance. Finish private iCloud upload, restore, account isolation and conflict/deletion handling for required data and standalone files; verify supported Jellyfin operations separately. Local annotations are not yet synchronized, and account sign-out warns before deleting that account's local data. This is a release requirement governed by ADR 0006, not a substitute for visual polish.
5. **Accept an exact candidate.** Compare the same DRM-free EPUB with Apple Books on the same device using comparable font size, theme and layout. Test ordinary/rapid/reversed/cancelled turns and boundaries; annotation creation/edit/removal/jump; typography/sidebar/resize/rotation changes; reopening; VoiceOver, larger text, Reduce Motion and keyboard/pointer input. Measure input-to-feedback delay, navigation completion, reflow and selection-observation cost. Rapid-turn tests must match every committed input in order with no duplicate or lost turns. Run relevant automated/native fixtures and separately record physical-device, real-book, live Jellyfin, two-device iCloud, accessibility, signing and distribution evidence. Keep 0.2 gate #28 and 0.3 gate #29 open until independently satisfied. Freeze, promotion and distribution remain separately authorized.

Implementation choices still requiring evidence include selection observation and energy cost, native-menu selection lifetime, changed-edition recovery and responsive animation techniques. Queue replacement/capping is not an open design choice: the owner explicitly withdrew it. Renderer failure must disclose uncompleted navigation rather than silently discard or replay uncertain turns. A different EPUB engine requires its own comparative proposal and migration proof; it is not a prerequisite for polish.


## Historical experiment: reduce resize glyph flashing (2026-11-03)

The owner requested smoother live reflow, suggesting a light blur or morph. Keep live coordinated geometry and every committed navigation input. EPUB.js currently clears its iframe views and redisplays the exact anchor for each resize; this can expose an empty paint as well as changing line breaks. Blur alone cannot fill missing text. A bounded offscreen synthetic probe confirmed empty DOM frames; it does not prove actual displayed pixels. A per-resize WebKit View Transition prototype reduced intermediate updates and added latency in one run, so it remains outside production source.

Next, test an asynchronous native image bridge over only each iframe replacement:

1. Prepare an image from an already painted page at resize/inspector start and refresh opportunistically after completed layouts. Never wait for image capture before advancing live geometry or processing input.
2. Clip the unscaled image to current bounds with theme-colored exposed edges, use it only over the brief replacement gap, and remove it as soon as the new text paints. Do not hold one frozen image for the entire animation. Evaluate a very short dissolve only if measured responsiveness holds; blur is optional polish after blank paints are covered.
3. Bind image ownership to book/session/layout generation. Discard stale captures, clear immediately for navigation, selection, errors and teardown, pass input through, and keep the layer out of accessibility. Reduce Motion/Transparency use immediate replacement. Unavailable/slow snapshots fall back to the current live renderer.
4. Compare real displayed frames, input latency, live intermediate width cadence, final anchors, selection/annotations and FIFO direction reversals against the unchanged baseline before integration. A regression in responsiveness rejects the prototype. Native Mac/physical device evidence remains separate from synthetic probes.

A true glyph morph would require stable text layout across line changes. Eliminating EPUB.js clear/recreate through in-place view reformatting is a larger renderer experiment, with pagination, annotation-hook and position-restoration risks. Neither an in-place engine change nor a native snapshot technique is accepted merely by recording this experiment.


Native trial outcome: the owner authorized implementation locally. The Mac-only image bridge is implemented in the uncommitted development patch; the earlier WebKit View Transition prototype remains rejected. Native safety/clipping/ownership checks passed and the real-WebKit run kept four live updates with no obvious added latency in that single comparison. Coverage was only partial in the empty-DOM message proxy (two of four), so the experiment has not established a complete visual fix or an accepted animation technique. The installed Mac trial is ready for owner comparison; keep the live renderer fallback and collect actual visual evidence before further tuning or claiming completion.


## Current resize presentation (owner revision, 2026-11-03)

The owner found live reflow with both the per-layout image bridge and slight blur still flashed too much. The current local Mac trial instead freezes one page image for the whole resize burst, using uniform aspect-fill while the native viewport moves. Reflow continues invisibly underneath; geometry-validated native paint plus quiet after the OS live resize ends triggers a 220 ms page dissolve and return to sharp. Intermediate completions update only the cache for the next burst. Input cancels the presentation immediately; stale completions cannot reveal a newer layout. A three-second lost-callback recovery protects against a retained cover after movement stops. Missing cached images use opaque themed paper rather than exposing intermediate rebuilt text. Reduced-effects settings take the immediate live fallback.

A synthetic real-WebKit run observed the same frozen cover at all four empty-DOM callback messages and retained ordered mixed-direction turns. This is lifecycle evidence, not proof of every presented pixel or acceptance of visual feel. Follow ADR 0010's revised visible-resize requirement and keep real-book, sustained performance and accessibility acceptance separate. No new rendering engine, persisted location format or publication authority is implied.
