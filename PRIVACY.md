# LibraVia privacy

LibraVia connects to the Jellyfin HTTPS server you choose. It has no publisher-operated account, advertising, analytics, or telemetry service integrated in app code. Reading still involves network requests to your server. That server's operator and Apple's system/TestFlight services have their own policies and may retain activity or diagnostics.

## Data handling

| Data | Purpose and retention |
| --- | --- |
| Password | Sent to your selected server for login. Cleared from the login field when submitted; not persisted by app code. |
| Access token, server/account identifiers | Stored in device-local Keychain for session restoration; removed by local sign-out cleanup. |
| Catalog queries, book identifiers, reading progress | Sent to your selected server for browsing, downloading, and progress synchronization. |
| Covers, author/profile images | Retrieved from your selected server and held in session memory; no public image service is used. |
| Downloaded and extracted books | Managed local account cache with a 1 GB budget; cache clearing retains reading positions/bookmarks. |
| Reading positions, titles, bookmarks | Local app support files scoped by normalized server endpoint, server ID, and user ID. Exact EPUB locations and bookmarks stay local; normalized progress is sent to Jellyfin. |
| Preferences, library selection, pseudonymous installation identifiers | Local preferences. The session identifier sent to Jellyfin is generated by the app rather than a hardware identifier. |

Reading-state files remain eligible for device backup. Preferences and server-specific pseudonymous identifiers can survive sign-out. Earlier endpoint-unaware namespaces are not migrated into the new account scope.

Sign-out attempts to remove credentials, account-specific cached books, and reading state. Clearing a download does not delete a server book. Local removal cannot erase server history or existing device backups. Failed or offline server-token revocation does not establish that the server has invalidated the token; sessions can also be revoked through the server administrator.

## Connection and document safeguards

Server fields start blank. HTTPS is required, including for reverse-proxy base paths. Embedded URL credentials, query strings, and fragments are rejected. The app uses Apple's certificate validation and refuses authenticated redirects. API networking uses ephemeral sessions with cookie, credential, and response caching disabled.

Ordinary SDK requests use an Authorization header. The official SDK's token-revocation endpoint places the token in its URL path; server and reverse-proxy operators should protect and redact access logs. No custom revocation protocol is substituted.

Keychain entries use unlocked, device-local protection and are not marked synchronizable. The app does not implement a biometric lock or guarantee password-memory zeroing. On macOS local book/state files are not separately encrypted by the app; OS account, disk, sandbox, and backup protections matter.

EPUB rendering uses a nonpersistent WebKit store and bundled local resources. Book scripts and unsolicited remote resources are blocked. Archive paths, sizes, counts, and extraction time are bounded; unsafe or unsupported books are rejected. These safeguards are not a certification against every hostile document or WebKit behavior.

## Privacy manifest and beta status

The privacy manifest declares no tracking or tracking domains. It declares own-app UserDefaults access (`CA92.1`) and app-container file timestamps (`C617.1`). These declarations do not replace App Store Connect privacy answers, the archive's aggregated SDK privacy report, or signed runtime verification.

The project is an MVP for internal testing. Final signed-app data handling, cleanup/cancellation, archive privacy, and cross-client synchronization still require verification as documented in VALIDATION.md. This repository document records app behavior; a distribution privacy-policy URL and publisher contact must be established before wider publication. Report sensitive concerns through SECURITY.md.
